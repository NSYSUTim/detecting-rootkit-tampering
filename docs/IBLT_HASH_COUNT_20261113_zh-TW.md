# 為什麼每筆更新三個 IBLT 位置：新增離線敏感度實驗

日期：2026-11-13。這是原研究完成後新增的離線驗證，不是當初選定三個位置時已做過的實驗，也不併入九次開機矩陣或其他原生實驗的分母。

## 三個位置的作用與目前選擇依據

IBLT 把同一項目的計數、識別值、inode、型態與校驗值累計到多個位置。相減後，若某格計數為 ±1 且通過校驗，即可還原該筆，並從它對應的其他位置消去它，讓更多格可以繼續剝離。這是逐步還原差異的機制；位置數會同時影響更新工作量與可剝離的分布，不是越多就一定越準。

既有程式固定更新三個位置。過去的容量實驗調整的是儲存格數／差異量的 1、2、4、8 倍，沒有比較二、三、四、五個位置。本次才新增該比較，沒有改寫既有 IBLT 或正式實驗資料。

本次主要條件沿用既有設計目標：**256 格、32 個差異項目**。三個位置在本次 2,048 組主要輸入均完整正確還原；兩個位置有 42 組失敗；四、五個位置亦均完整還原。三個位置是這批測試中達到全部正確還原的最少位置數，且其離線 Python 建表、解碼耗時中位數均低於四、五個位置。這支持在目前設定下保留三個位置，不能推成三個位置在所有容量、差異量或輸入分布下最佳。

## 執行前固定的方法

- [原始規約](../results/iblt_hash_count_20261113/protocol.json)於 2026-11-13 13:52:58（臺灣時間）寫入，原始執行於 13:53:05 開始，規約 SHA-256 為 `472342278a42d6034ac267100c589a9c8e2b89c88ea9f442232db8916dcba690`。這是本機執行前鎖定紀錄，不是第三方預先註冊。
- 比較 k=2、3、4、5。每組使用完全相同的輸入項目與種子，隨機安排四種版本的執行順序；容量與位置數不參與輸入生成。
- 主要條件的 missing 與 substitution 模式各 1,024 組，共 2,048 組配對輸入。missing 全為上游獨有；主要條件的 substitution 正負各 16 筆，合計 32 筆對稱差異。
- 另固定檢查不同差異量、容量及第二種位置生成方式，共 30 個條件、9,216 組配對輸入、36,864 次版本解碼。這不是 36,864 個獨立輸入；不同容量及位置生成方式還會重用相同輸入，不以全部版本執行次數作獨立樣本數。
- 第一種生成方式保留既有前二／前三個位置，依固定鹽值擴充第四／第五個位置；第二種對所有位置使用同一種帶種子混合規則，檢查有限的位置生成方式敏感度。
- 主分析從隨機且唯一的 64 位元識別值生成項目，直接建立帶正負號的差異表，沿用原容量模擬方式。每次以完整 token 多重集合核對真值；不能只看解碼器的成功旗標。共同項目抵銷與重複項目限制另作控制，不列入主結果。
- 規約先指定：三個位置必須在主要條件下對二、四、五個位置都呈現較高的正確還原率，且三項配對 exact McNemar 檢定經 Holm 校正後均達 α=0.05，且沒有錯誤成功，才稱為三個位置的嚴格還原優勢。沒有依結果改變條件、種子、試次數或停止規則。

## 解讀界線

本結果只驗證隨機唯一識別值下的離線差異還原，未驗證原生 eBPF 更新成本、實際名稱雜湊、惡意構造碰撞或 rootkit 檢出率，亦未修正 XOR 版 IBLT 的重複差異限制。三個位置在此設定是有新增證據支持的工程折衷；它不是全域最佳、沒有碰撞、一般多重集合都能還原或所有環境效能較好的證明。這些新增資料不回填原矩陣實驗的樣本數、信賴區間、成本或選參數歷史。
