# Ubuntu 26 LTS 重跑與診斷紀錄

這個資料夾保存 2026-11-14 至 15 日在 Ubuntu 26.04.1 LTS 隔離 VM 取得的新量測、凍結來源與追加診斷。它是獨立的待確認版本；儲存庫其他位置的 Ubuntu 22 資料、正式書面、PDF、海報及入口保持原位。本次沒有將 Ubuntu 26 展開為預設版本，也沒有搬移 Ubuntu 22。之後是否切換版本與目錄結構，另行確認。

## 內容與環境

- [2026-11-14 重跑結果與限制](rerun_20261114/README_zh-TW.md)：九次開機主矩陣、量測品質、載入順序、兩個核心建置的適用性、公開樣本、成本、外部比較與離線容量。
- [2026-11-15 完整資料診斷](followup_20261115/結果說明.txt)：73 筆差異的再現、完整名稱與 inode、兩端 IBLT、未還原項目、容量交叉確認與 OEM 動態補驗。
- [追加診斷的逐筆重算結果](followup_20261115/VERIFIED_FINDINGS.json)與[原始封存](followup_20261115/followup_evidence.tar.gz)。原實測程式／二進位另見 [來源封存](followup_20261115/frozen_existing_sources.tar.gz)。
- [工具鏈](rerun_20261114/MEASURED_TOOLCHAIN.json)與[核心建置](rerun_20261114/KERNEL_MATRIX.json)：主要為 7.0.0-43-generic，適用性另測 7.0.0-1018-oem；兩者同屬 Linux 7.0，不能沿用原 6.8／6.5 的跨系列主張。
- [原始證據清單](rerun_20261114/EVIDENCE_MANIFEST.json)、[本資料夾逐檔雜湊](FILE_SHA256.json)及[儲存方式](STORAGE_LAYOUT.json)。沒有放入 VM 磁碟、登入憑證、原始記憶體轉儲或新版書面草稿。

VM 使用 4 vCPU、8 GiB RAM；BCC 0.35、Clang/LLVM 21.1.8、GCC 15.2、Python 3.14.4。原生研究在沒有 IPv4／IPv6 預設路由的隔離 VM 內執行。來源快照中的舊日期客體路徑是凍結入口約束，不表示這次仍使用舊 Ubuntu。

## 73 筆差異的追加診斷

固定原參數與種子、重新建立檔案後，第一組的一百次列舉均完整還原。依事前固定的診斷搜尋規則檢查 330 組真實 inode 配置後，重現了兩筆不同項目落在同一組三格的情況：

| 新重現中的名稱 | inode | 256 格下的位置集合 |
|---|---:|---|
| `J2SZQ2_caraxes_8W` | 1639255 | 24、118、225 |
| `MF9_caraxes_83PWJ` | 1639261 | 24、118、225 |

兩筆識別值不同；其餘 71 筆剝離後，殘留三格的計數皆為 +2，沒有可繼續剝離的純格。新重現的一百次結果一致；未修改的原探針五次亦一致。固定相同檔名、inode 與種子，改為 512 格及 1,024 格後，各十次與原探針各五次均完整還原。

這是位置碰撞，和相同 token 重複出現是不同限制。加大容量解開這一組碰撞，不代表任意輸入均必定解碼。診斷搜尋刻意尋找失敗，不作一般還原率估計。歷史失敗批次未保存完整身分資料，因此不能將這兩個名稱追認為歷史那兩筆。

本輪另在 OEM 核心補跑八種正常動態條件，各固定十次；80 次均確實重疊建立、改名、刪除，量測有效且兩端一致。先前刪除競態的三開機、30 次真正觸發補驗仍單獨保留。

## 核對與還原原始資料

在儲存庫根目錄使用 Python 3.12 或更新版本執行；僅核對與資料還原使用標準函式庫，不需要 root、eBPF 或載入模組：

```bash
python ubuntu26/verify_bundle.py
python ubuntu26/verify_bundle.py --restore reproduced/ubuntu26_review
python reproduced/ubuntu26_review/followup_20261115/verify_followup.py
```

第一個命令核對本資料夾全部檔案、分片、原始來源與追加診斷封存雜湊，並串流核對大型封存可重組為原始位元組。第二個命令只寫入尚不存在的新目錄，重建原大型封存、1,250 個逐事件檔及追加診斷。第三個命令從保存的完整資料獨立重播 235 次原生診斷／交叉確認、330 組離線真實 inode 輸入及 80 次 OEM 動態控制。

185,280,537-byte 的原 Trace 封存以四個不超過 48 MiB 的分片存放；逐事件檔已在原封存內，不重複存第二份。重組後 SHA-256 為 `391c1bc7731661e76ff79d8001dac782b4a492914929bebb8a9af4d9aec1fd9e`。Linux 原始檔名與 Windows 安全名稱的對照保留；原始封存內容及雜湊未改。

原實驗助手原樣保存供追溯，其中部分保留原 VM／儲存庫路徑。它們不是跨環境的一鍵部署程式；可攜核對入口為本節列出的命令，路徑調整見 [PORTABILITY_NOTES.json](PORTABILITY_NOTES.json)。原生重跑所需模組只適用於相容的隔離研究 VM，不在一般主機執行上述離線核對時載入。
