# 現行收集入口與共同工具比較確認規約

本規約在正式確認前固定。先導包括官方 zygarde 正常執行、tracefs 入口的正常列舉及真實 nmissed 注入，另存不併入確認分母。原始凍結程式、兩輪補充資料與原正式書面保留。

## 現行入口

以 scan_directory.py 作為新版本入口，沿用原合併 BPF 程式、指紋、IBLT 及接受規則。入口探針改由明確 tracefs 事件附掛，列舉前後核對事件定義、ID、hits 與 missed；沿用返回 profile、BPF recursion_misses 及還原指紋核對。任何必要品質資料缺少、事件身分變動、計數倒退或窗口內漏失皆拒判。僅宣稱覆蓋這些可觀察機制，不宣稱任意核心對手下完整。

在原 6.8.0-138-generic VM 執行。新目錄保存所有嘗試，原參考程式及既有模組 SHA-256 前後核對。新診斷模組只用於真正探針重入注入，利用無效名稱的 filldir64 錯誤返回路徑，不改寫任何列舉結果；每次 finally 卸載。未安裝或升級客體套件。

正常、重排、新增、名稱增長／縮短、inode、型態、移除、filldir 隱藏、getdents 隱藏、政策過濾及等長替換共十二種狀態，緩衝區 128 與 4096 bytes，各三次。每個狀態／緩衝區另有無探針實收控制。未實際注入不算成功陽性。filldir 隱藏另以兩種載入順序、4096-byte 緩衝區各三次。定位小表故障另以八格、十六個移除項目確認差異仍警報而不能完整定位，不算完整還原成功。

入口漏失做十個獨立窗口，每窗由診斷模組製造十次真實重入，要求入口 missed 正增加且拒判。每個窗口前後各一個正常控制，要求有效一致。另以 maxactive=1、十六個並行掃描確認返回漏失窗口拒判，再以 maxactive=256 作兩次循序對照。故障控制分母獨立。名稱邊界與過小緩衝區亦另列。

## zygarde 比較

官方 Linux amd64 v0.2.1 執行檔 SHA-256 固定為 04e4f9c0160a208671f106f0a0f8d1bbe020f785925af0b98be0910994467389。先用未改寫的官方執行檔，僅選 hidden_file、停用監督子程序隔離，使目標 comm 和 C 掃描器均為 d9_enum_probe。只改存放檔名，不改二進位內容；記錄兩者實際模組操作計數。官方全目錄範圍不拿來和單一目錄直接比速度。

共同功能試驗在 /var/tmp 預先確認不存在的特定受控檔名上進行，十二種狀態，各五次、方法先後隨機配對。兩工具使用同一已載入模組與同一目錄。每種狀態保存無探針實收控制、獨立預期差集、模組計數及完整工具輸出。

共同目標是核心產生而回傳缺失的名稱：名稱增長、縮短、移除、filldir 隱藏、getdents 隱藏、政策過濾及等長替換，共七種；正常與重排為對照。新增、inode、型態另作本文身分差異目標，不把它們混入共同名稱目標的召回分母。zygarde 的目標目錄發現、全工具狀態、其他目錄發現、錯誤與跳過分開。錯誤／跳過不當乾淨陰性。政策過濾是輸出差異，不據此判定惡意。

效能用固定來源 08ccebd8fdcc28c56dc6251cad0683b7c9344bd1 的最小轉接版，只讓 scanDirs 和檢查檔使用指定目錄，另有可選的列舉後稽核輸出；不更改 BPF、名稱集合、缺失重掃或判定演算法。來源差異與工具鏈雜湊公開。功能先導須與官方版本對同樣輸入的目標發現一致，否則不得當同演算法成本基線。

正常靜態目錄 128、4096、65536 個一般項目，各方法每條件一個暖機及五個主要配對，方法順序隨機。主要指標是每次完整程序執行的牆鐘時間，包含其實際載入、附掛、列舉、品質檢查、輸出與清理，兩者目標目錄相同。記錄 GNU time 的 user/system CPU 與 max RSS，後者不是所有並行程序及核心 map 的總記憶體。轉接版的額外檢查檔與是否寫稽核另標。不要沿用原十一倍或邏輯資料量倍率。

預計在同一 VM 的三次開機重複共同功能與成本確認。先完成當次並卸載全部受控模組，確認無其他研究收集程序，再重開機；核心版本若變動即停止，不把它當相同條件。每次結果以開機分層，無效、未注入、先導及故障分開，不能合併舊分母。若環境或工具無法達成三次確認，保留實際已得樣本與具體阻礙，不宣稱三次完成。

Synacktiv 公開展示沒有完整自動判定工具可直接執行，其逐項資料設計與本文自製基線分開描述。既有 Trace of the Times 與 Decloaker 數值保留原範圍。rkchk 需要不同自訂核心且檢查目標不同，本輪不為工具數量而改動原環境；沒有其新比較數值。
