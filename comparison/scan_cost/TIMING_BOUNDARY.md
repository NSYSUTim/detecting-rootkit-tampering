# 計時終點的原始碼核對

正式計時前另核對固定版本 internal/core/runner.go。檔案元件 Run 返回後，上層仍會將 findings、canary 與錯誤轉成最終狀態。因此僅量檔案元件的迴圈還不足以符合原規約的「形成判定」終點。

正式轉接版沿用相同規約，計入兩個實際區段：觀測與檢查檔準備好後至檔案元件離開前的掃描及比較，以及上層 RunCell 在清理後完成 findings、canary、錯誤分類的原有處理。兩段使用相同單調時鐘並相加，掃描段、判定後處理與總和分別保存。中間原本延後執行的 BPF／讀取器清理及最後稽核輸出排除。不是以重新執行一份簡化判定取代原碼，也未改 canary 或 findings 的判斷。

第一次先導的核對旗標錯誤與第二次通過的 36 筆功能確認全部保留，兩者只作先導。最終轉接版另以第三次先導重新確認後才開始正式三開機成本資料。這些檔案與舊 BUILD／patch 在各部署 ZIP 中保存，正式版本 BUILD.json、adapter.patch 另列。此核對不變更目錄大小、容量、方法順序、暖機與重複數，也不將先導的時間混入確認。
