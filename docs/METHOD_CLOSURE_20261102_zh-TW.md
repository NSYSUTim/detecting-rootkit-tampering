# 目前方法的結案工作與共同工具比較

原版 CARAXES 已完成另一組三開機實測：getdents64 模式 120 次警報並還原，正常 60 次一致，filldir 模式 120 次實際清單截斷但未警報。這組分母不與先前實驗合併，兩端一致不代表沒有隱藏。詳見[原始資料、原因與比較](ORIGINAL_CARAXES_20261102_zh-TW.md)。

本頁保留六項結案工作及完整程序比較的範圍。其後已另完成[相同輸入及掃描判讀範圍的三開機成本比較](SCAN_COST_COMPARISON_20261102_zh-TW.md)，正式書面更新為 revised39。兩組計時分開，不以其中一組取代另一組。

本輪以原六項結案清單為範圍，完成目前執行入口的還原核對、入口探針統計、修改後驗證及最接近工具的共同實驗。沒有把入口缺口僅改列未來，也沒有只停在 zygarde 的設計比較。初版實作及其數據仍凍結，新版本入口為 scan_directory.py。

## 現行入口的確認

72 次狀態測試中，57 次實際身分差異全部正確警報、精確還原且通過指紋核對，其餘有效一致。三次 128-byte 緩衝區新增未施作成功，另列而不算陽性。24 次無探針實收控制均符合預期。另有六次 filldir 隱藏載入順序確認，均正確判讀與還原。

十個入口重入故障窗口各製造十次真實 nmissed，全部拒判，前後二十次正常控制有效一致。漏失發生在事件的全域窗口，不代表十次目標列舉本身各漏十筆。注入使用新診斷模組，在探針處理期間呼叫 filldir64 的無效名稱返回路徑，不改寫目錄項；這是統計門檻整合驗證，不能稱為修復了原矩陣實驗資料中已證明的錯誤一致。

返回漏失窗口的十六次列舉全部拒判，兩次循序對照有效一致。兩次八格／十六個移除項目的試驗保留差異警報而不宣稱完整定位。名稱邊界正常，過小緩衝區拒判。矩陣實驗的 256 格設定未改成八格。

## zygarde 共同功能結果

官方 v0.2.1 執行檔核對發布 SHA-256，內容不改，僅選 hidden_file 並以原有 PATH 設定加入獨立測試目錄。兩工具使用相同的受控模組及目錄，程序名稱符合相同的模組條件。每個開機十二種狀態、各五次，每次方法順序隨機，三個不同 boot ID 都是 Linux 6.8.0-138-generic。

| 判定目標 | 本文現行入口 | zygarde 官方檔案元件 | 解讀 |
|---|---:|---:|---|
| 共同的缺失名稱案例 | 105/105 | 105/105 | 共同目標下本研究沒有顯示檢出率優勢 |
| 正常與重排對照警報 | 0/30 | 0/30 | 只限受測目標目錄，其他目錄發現分開記錄 |
| 新增項目 | 15/15 | 0/15 | zygarde 此元件只報核心產生而回傳缺失的名稱，新增為不同目標 |

| 只改型態 | 15/15 | 0/15 | 本文身分含型態，名稱集合未改變 |

三開機共 360 筆工具觀察，36 次無探針控制均符合預期，沒有把工具錯誤或跳過當成乾淨結果。額外三十六次轉接版功能核對與官方版本的目標發現一致，不併入上述官方工具分母。政策過濾算輸出差異，不由此判定惡意。此結果不是所有 rootkit 的偵測率。

## 成本與大目錄事件完整性

效能轉接版只改目標目錄、檢查檔所在目錄及可選的事後稽核輸出，BPF 與比較演算法不改。正式計時關閉稽核輸出。三開機各三個目錄大小、五個計時配對，共 45 個配對與 18 次暖機。每次使用新程序，沒有清除檔案系統快取。

| 一般項目數 | 本文各開機耗時中位數 | zygarde 轉接版各開機耗時中位數 | 另次入口／回傳名稱數稽核 |
|---:|---:|---:|---|
| 128 | 2.126–2.278 秒 | 0.569–0.619 秒 | 129/129，三次相同 |
| 4,096 | 2.177–2.278 秒 | 0.569–0.621 秒 | 4,097/4,097，三次相同 |
| 65,536 | 2.028–2.379 秒 | 0.723–0.821 秒 | 15,343/65,537，三次相同 |

計時包含程序啟動、各自載入與附掛、列舉、品質檢查、輸出和清理。本文包含 BCC 即時編譯，zygarde 使用預編譯 BPF，所以不能把差距歸為指紋或 IBLT 的演算法速度。128 與 4,096 項時，逐配對計算後的各開機中位數顯示本文約為轉接版 3.50–3.73 倍，不能宣稱全面更快。

65,536 項的稽核顯示 zygarde 入口名稱集合少於實收名稱，新增的一筆為檢查檔。此流程先完成 os.ReadDir 再讀 ring buffer，固定 4 MiB 不足以保存全部逐項事件，所查實作沒有保存預留失敗計數。這支持此受測流程的入口觀測不完整，不是隱藏攻擊檢出試驗。大目錄的較短耗時不能當成同等完整觀測下的速度優勢，也不表示正常資料已有隱藏。本文的還原名稱可讀性仍弱於逐項名稱工具。

GNU time max RSS 的各開機中位數，本文為 126,632–126,764 KiB，轉接版為 82,880–87,320 KiB。這是其回報的使用者程序指標，不含核心 map，也不是同時占用的程序群組記憶體總和。舊 12.02 KiB 是邏輯摘要，不能拿來與這些 RSS 或 zygarde 4 MiB ring buffer 作整工具記憶體勝負比較。

原 4.76 倍、自製逐項 map 的約十一倍，以及前輪合併狀態版約四成改善，均維持原版本及計時定義，不和本輪新程序成本混算。

## 未完成嘗試與控制程式修復

原規約首次以混合內容的 /var/tmp 作目標，完成九十筆觀察後，官方工具在 getdents 過濾條件逾時。該條件的無探針控制沒有留下有效記錄，不能據此判定 zygarde 漏報或一般工具缺陷。此未完成確認及堆疊完整保留，修訂規約後才在獨立目錄重新進行三開機確認，兩者分母不合併。

另查出舊 getdents 控制模組在重疊 memmove 後重新讀取已被覆寫的 d_reclen。離線的 216-byte 輸入會算出 24,977-byte 輸出長度，修復為搬移前保存長度後得到正確 176 bytes。這證實控制程式缺陷，不單靠此模型宣稱已分離 Go 逾時的完整原因。修復版另以混合長短記錄原生確認，12 次無探針控制、4 次本文量測及4 次官方工具均符合預期，這二十次不併入共同比較或原分母。

原來源及資料不覆寫。舊正式受測輸出仍由獨立預期差異核對，沒有證據顯示此缺陷曾使其已保存結果錯誤；也不能把修復說成原實驗時已存在。細節與重現程式在 comparison/controls。

## 其他相關方法的處理

zygarde 是最接近、可直接執行的自動化檔案元件，已完成共同實驗。Synacktiv 公開的是 filldir64 名稱輸出展示，沒有可直接執行的完整自動判定器，保留設計比較，不編造其偵測率。本文自製逐項 map 基線仍獨立標示。Trace of the Times 與 Decloaker 保留原實驗及其限制，不把不同版本、不同目標的結果混算。rkchk 官方固定版本明示需要其擴充 Rust API 的自訂核心，且其特定記錄結構檢查與本題不同，不為增加工具數而更換矩陣實驗核心，保留此缺口。
