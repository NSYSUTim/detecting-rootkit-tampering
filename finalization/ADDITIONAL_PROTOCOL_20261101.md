# 結案補強的差異及漏失整合確認

此追加規約在十次正常／邊界整合確認完成後、以下試驗執行前固定。先前十次資料另存，不合併成原主實驗或兩輪補充的分母。

沿用同一受保護虛擬機及既有環境，只在新目錄保留資料。載入的僅是原第二輪已驗證的受控變更模組，不執行新取得的公開 rootkit。開始時必須沒有其他研究模組載入；保留模組與舊程式的雜湊。所有載入皆以 finally 卸載，未能卸載就停止並記錄，不再繼續其他試驗。

## 身分變更

使用原有 phase2_transform 模組的七個模式：重排、新增、名稱加長、名稱縮短、inode、型態、移除；等長替換使用原有 getdents_substitution 模組，共八種狀態。目錄含 phase2_subject、d9_swap_a_0000、other_a、other_b，緩衝區為 256、4,096 bytes，各狀態各緩衝區重複兩次，共三十二次，另有四次未載入對照。先用無探針的相同 C 程式收集原生回傳記錄，由既有獨立 oracle 核對實際變更；未實際注入的案例不得算成成功陽性。

完整量測的結果須與無探針控制及獨立預期差異相符。除重排預期一致，其餘已實際注入的模式預期差異警報及通過核對的還原。記錄實收名稱、inode、型態，避免把沒有動作的模組算成成功偵測。

## 返回漏失

未載入變更模組時，將既有合併收集器的 maxactive 設為 1。新建四千零九十六個短檔名，啟動十六個掃描器同一窗口並行，緩衝區為 4,096 bytes。若窗口實際 missed 增量大於零，所有該窗口列舉應拒判。若未發生漏失，記為未施作成功，不替換這次紀錄。另用 maxactive=256 循序兩次正常對照，須有效且一致。

這只驗證已覆蓋的返回窗口與新程式整合，不宣稱原生注入了 BPF recursion_misses 或已量得入口 perf kprobe 的全部 nmissed。

所有失敗、無效與未施作案例依序保存，新增分母獨立列出。這不是九次開機矩陣的重跑，也不將它寫成新的未知 rootkit 偵測率。
