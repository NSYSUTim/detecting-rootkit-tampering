# Ubuntu 26.04.1 LTS 完整重跑

本輪開始於 2026-11-14。所有數值來自新建的隔離 VM；4 vCPU、固定 8 GiB RAM，主機為 Intel Core i7-1355U、約 32 GB RAM。套件在正式量測前安裝官方更新後凍結：BCC 0.35、LLVM/Clang 21.1.8、GCC 15.2、Python 3.14.4、glibc 2.43。Python 版本依執行時紀錄，LLVM/Clang 依 `clang-21` 等實際版本套件；不以 `python3`、`clang` 轉接套件的舊版號代替。對應套件清單另存於 `MEASURED_TOOLCHAIN.json`。

主要核心為 `7.0.0-43-generic`，適用性核心為 `7.0.0-1018-oem`，同屬 7.0 系列。VM 無 IPv4/IPv6 預設路由。原生測試依序執行；先導、故障控制、正式資料與補充驗證分別保存。

## 主要結果

- 主矩陣：9 次開機、1,296 批、25,920 次列舉。D9 告警 576/576、誤報 0/720；11,520 次陽性列舉全部精確還原。計數基準 432/576。MAD 召回率／誤報率 5.03%／7.50%，時間上界 2.95%／4.03%。
- 適用性：兩核心各三次開機，共 5,760 次靜態量測與 264 次無探針對照；4,560 次實際差異均正確還原。480 次動態對照均一致，其中 1 次未與三種變更全部重疊，使 1 次 campaign 未達完整原採納條件。原紀錄保留，補充 OEM 動態對照的 79/80 次實際重疊另列。
- 品質與載入順序：90 個真實返回漏探針視窗中的 1,680 次列舉均拒判；1,800 次載入順序試驗、其中 720 次完整判定／還原，均符合預期。入口閘門另有三次開機確認。
- 公開 CARAXES：三次開機、兩種載入順序。getdents64 模式 120/120 告警並還原 3 筆；filldir 模式 120/120 完成異常告警。本次後者接受／收到 36/36，另有 34 筆未出現，僅遭拒絕的一筆可識別，其餘 33 筆未走訪後綴未知。
- 現行回歸：960 次受控掃描，555 次實際差異全部告警且精確還原，405 次無差異均不告警；120 次靜態與 240 次動態正常對照無誤報。原 30 次刪除競態中僅 15 次實際觸發，補充三次開機的 30 次已逐筆確認真正刪除遭拒絕檔案，均一致。
- Decloaker：九次開機、720 次掃描；180 次隱藏告警 0 次、540 次對照誤報 0 次。這反映其路徑可存取性判準，不能推論對其他隱藏方式的表現。
- 共同情境 D9：保留全部 1,000 批與原嚴格旗標，1 個陽性批次未完整還原。73 差異批次量測有效且告警，但只剝離 71 筆；未更換該批、種子或容量。原收集器從下一個預定索引續跑。
- 時間基準：完整五情境收集，四情境主比較每種分組評估 100 次。fun 召回率／FPR 100.00%／4.59%，seq 100.00%／9.10%。公開評估器以測試標籤挑最高 F1 閾值，屬偏樂觀估計；另保留固定 alpha=0.05 與五情境結果。

## 成本與離線容量

現行完成檢查在 65,536 個項目時，三次開機中位數為 82.14–99.21 ms；僅接受項目版為 84.68–113.33 ms，配對比值 0.89–1.03。每次先暖身，再測五對。此計時不含 eBPF 編譯、載入及附掛。

較早主矩陣實作的單開機逐筆基準，在 65,536 項目時固定摘要 142.12 ms、逐筆記錄 1,479.92 ms，邏輯資料量分別 12.02 KiB、17,920.55 KiB。兩種時間邊界與實作版本分開，不能互換。舊版完整方法／單純列舉倍率為 4.62。

容量網格沿用種子 12009，四種格數倍率各 2,560 次，成功數依序 441、2,406、2,550、2,560。補充六組純刪除模擬因原先未保留種子，本輪明列新種子 20261114；不宣稱隨機試次會逐筆等同舊表。二／三／四／五位置敏感度沿用原 20261113 固定規約，完整重跑 36,864 次版本解碼；這是離線 Python 模擬，並非原生 eBPF 變體或全域最佳性證明。

## 相容性與原始失敗

LLVM 21 的 map-value 索引界限調整改寫兩個目前 BPF 檔案；執行時索引仍為原來的 `index & 255`，指紋、種子與決策規則未改。CARAXES 加入兩處 socket API 型別轉換。另一公開過濾範例的四處固定長度 memcmp 改用 NUL-aware strncmp，避免短末筆名稱觸發 FORTIFY，原先崩潰紀錄保留。

未修改的固定版本 Diamorphine 編譯成功，但第一次 insmod 在 MOV-to-CR0 處崩潰，正式隱藏批次未開始。轉儲中 CR4.CET 已設定而程式欲清除 CR0.WP，與 [Intel 手冊的限制](https://cdrdv2-public.intel.com/843836/325384-sdm-vol-3abcd-dec-24.pdf)一致；它列為來源版本特定的載入相容性失敗，不算偵測結果。

額外 CLI 夾具的目錄順序使 CARAXES 輸出不合法紀錄，掃描器正確拒判，資料保留於原嘗試。改用正式實驗原目錄的 12 項介面核對通過；不是替換正式樣本。修正版壓縮控制模組另測 12 次，不併入原主矩陣。

## 證據與重算

`observations/` 保存原始批次、三開機封存、成本、離線試次與獨立重算。`REPORT_EVIDENCE_VALUES.json` 為數值來源，`REPORT_NORMALIZED_METRICS.json` 為報告格式化數字；先導及原始失敗不會被刪除或併入正式分母。凍結四個實際來源樹、原規約與移植差異另存。歷史客體目錄名稱是原入口路徑約束，並非宣稱本次仍使用舊 Ubuntu。

主矩陣沿用原收集器，未記錄後來新增的全部漏探針計數器；不把未記錄值填成 0。共同情境 D9 的壓縮交易紀錄以原版保留的欄位為準，其精確還原旗標由凍結收集器產生；不能宣稱其中未保存的核心 IBLT 全表也可事後重播。全量新證據及稽核範圍見各 verification JSON。
