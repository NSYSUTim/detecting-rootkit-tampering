## 現行入口的確認

72 次狀態測試中，57 次實際身分差異全部正確警報、精確還原且通過指紋核對，其餘有效一致。三次 128-byte 緩衝區新增未施作成功，另列而不算陽性。24 次無探針實收控制均符合預期。另有六次 filldir 隱藏載入順序確認，均正確判讀與還原。

十個入口重入故障窗口各製造十次真實 nmissed，全部拒判，前後二十次正常控制有效一致。漏失發生在事件的全域窗口，不代表十次目標列舉本身各漏十筆。注入使用新診斷模組，在探針處理期間呼叫 filldir64 的無效名稱返回路徑，不改寫目錄項；這是統計門檻整合驗證，不能稱為修復了原矩陣實驗資料中已證明的錯誤一致。

返回漏失窗口的十六次列舉全部拒判，兩次循序對照有效一致。兩次八格／十六個移除項目的試驗保留差異警報而不宣稱完整定位。名稱邊界正常，過小緩衝區拒判。矩陣實驗的 256 格設定未改成八格。

## 控制程式修復

舊 getdents 控制模組在重疊 memmove 後重新讀取已被覆寫的 d_reclen。修復方式是搬移前保存長度。修復版另有 12 次無探針控制與 4 次本文量測，結果均符合預期；這些確認與原正式實驗分開報告。

## 其他相關方法的處理

Synacktiv 公開的是 filldir64 名稱輸出展示，沒有可直接執行的完整自動判定器，保留設計比較，不編造其偵測率。 本文自製逐項 map 基線仍獨立標示。 Trace of the Times 與 Decloaker 保留原實驗及其限制，不把不同版本、不同目標的結果混算。 rkchk 官方固定版本明示需要其擴充 Rust API 的自訂核心，且其特定記錄結構檢查與本題不同，不為增加工具數而更換矩陣實驗核心，保留此缺口。
