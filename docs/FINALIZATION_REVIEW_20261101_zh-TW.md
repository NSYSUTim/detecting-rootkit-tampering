# 目前方法完成內容與書面審查依據

本輪完成既定兩端一致性方法的具體補強，更新正式書面為 revised34。完成項目是還原結果核對、可取得的 BPF 程式略過檢查、整合回歸與原生確認，以及最接近公開工作的比較。原九開機與兩輪補充數據、程式及來源鎖保持原樣。沒有把所有研究限制改成已解決，也沒有擴大到一般程式監控、前後觀測邊界或 /proc。

## 研究主張

專用 C 掃描器自行發起一次完整目錄列舉；eBPF 觀察同一次列舉的 filldir64，C 程式解析自己收到的 getdents64 緩衝區。它不是在背景替所有 ls 取得記錄。兩端以已接受項目為基準，建立固定大小指紋及 IBLT，判斷觀測邊界內的身分是否不同，嘗試還原少量差異識別值。警報不是惡意性判定，也不是磁碟完整真相。

最接近的 zygarde 也採這組觀測位置，所以不能把「比較這兩端」當成獨有貢獻。可支持的貢獻是接受規則、同次完整列舉對齊、固定摘要、雙向差異識別值、量測失效處理與受控驗證的整合。名稱可讀性是取捨：zygarde 可回報缺失名稱，本文 IBLT 不還原原始名稱。

## 反例說明與尚存問題

兩份 X 寫進同樣位置，X XOR X 為零，但計數仍為 2，沒有 ±1 起點。兩端各兩份 X／Y 且三個位置相同時，計數和內容全部抵銷，舊解碼器會誤報空差集成功。新核對會發現空差集指紋不等於實測端點差，保留差異警報並標為不能完整定位。

沒有重複也能失敗：相同反例 X、Y 各一份，在 256 格時同落三格，計數都成零但 XOR 內容不為零，沒有可剝離的單筆儲存格。這是分布限制，所以「32 項以下必定成功」不成立。原 256 格維持不變，小表故障測試不是把正式設定改為 8 格。

已知反例的指紋不同是算出的事實，不能由 h(X)≠h(Y) 一般性推出 2h(X)≠2h(Y) mod 2^64。公開 FNV 規則也沒有主動碰撞安全證明。此限制應明列，無須用沒有實作的密鑰保護消除它。

目前仍有限容量、機率式比對、入口 perf 探針的部分不可見漏失、其他掛接方式未驗證、可信偵測器假設及有限環境證據。這些需要限制敘述與合乎範圍的主張，不代表所有方向都必須做完才能完成專題。若投稿場域要求特定強度或完整共同工具評估，才需按其要求補資料，不能保證投稿或得獎。
