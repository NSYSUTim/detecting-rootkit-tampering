# 受控目錄緩衝區搬移修復

原 getdents 控制來源以 memmove 壓縮回傳記錄，之後再讀 entry->d_reclen 更新位移。當目的區與來源區重疊，entry 指向的長度欄位已可能被覆寫。修復是在搬移前保存原長度，之後用該值搬移及更新位移，不改原檢查目標。

reproduce_compaction.py 在使用者空間重現具體反例：216-byte 輸入舊邏輯計算成 24,977-byte 輸出，修復邏輯為正確176 bytes。這是預計越界複製長度，不是聲稱 Python 實際讀出該長度的記憶體。

原來源、正式資料及比較分母不覆寫，修復確認不算共同工具比較的額外成功樣本。

首輪混合 /var/tmp 比較未完成且控制輸出不有效，不能把它算成官方工具漏報。上述來源缺陷與實際 Go 逾時的完整因果鏈沒有被本模型單獨分離，不作超出證據的歸因。修訂後三開機比較用獨立短名稱目錄，原控制輸出均另經核對。

來源及修復差異見 PROVENANCE.json、buffer_compaction.patch。原件保留在 attack_variants/d8_getdents_controls，不修改凍結檔。新模組只用於隔離研究 VM 的控制驗證，不含持久化或權限變更功能。
