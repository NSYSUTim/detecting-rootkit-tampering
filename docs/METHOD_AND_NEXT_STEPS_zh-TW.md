## 目前比較什麼

比較同一次完整目錄列舉中，核心 filldir64 最外層回傳 true 的項目，與專用單執行緒 C 掃描器反覆呼叫 getdents64 直到回傳 0 所取得的項目。名稱位元組、inode、型態共同構成身分。只計最外層且已接受的呼叫，避免包裝巢狀重複計數及把正常的緩衝區不足重送計入。

控制程式在放行前登記量測執行緒，單執行緒掃描器的 TID 與 PID 相同。兩端同步建立 F=(n,A,B) 與 IBLT，實驗每次都解碼。摘要大小在容量固定時固定，逐項處理時間仍隨項目數增加。順序重排不算身分差異。

指紋決定是否有差異，IBLT 還原識別值、inode、型態，不還原名稱。256 cells／32 個差異是經驗設計目標及八倍預留，不是任何輸入必定解碼成功的界線。公開種子與 FNV 不提供對主動碰撞的密碼學保證，兩總和未證明獨立，也沒有任意多重集合差異的形式漏報上界。只換名稱且 inode 與型態不變時，h₁ 相等會使 h₂ 相等。非線性混合本身不足以證明多筆總和獨立。

本實作以計數與 XOR 累計 IBLT，解碼從計數為 ±1 且通過校驗的儲存格開始。一端兩份 X、另一端為空時，三個位置的內容為零、計數為 2，無法剝離；兩端各兩份 X／Y 且位置相同時，整表歸零而原解碼器錯誤回報成功。無重複也能因位置分布而失敗。整合版已接入還原指紋核對，錯誤空差集不能標為通過核對的完整還原；此核對不消除碰撞風險，也不改變原 XOR 結構。

下表是身分分支的判讀，新增完成檢查的結果分開保留。

| 狀態 | 輸出與解讀 |
|---|---|
| 量測資料缺少、失效或品質窗口不可靠 | 拒判／無效，不算一致或警報；保留原因，另次量測是新交易 |
| 量測有效、指紋相同 | 這次未觀察到邊界內差異，不是內容必然相等的證明 |
| 指紋不同、解碼完成且還原核對通過 | 差異警報及通過核對的兩端獨有識別值；仍非無碰撞證明 |
| 指紋不同、解碼或核對失敗 | 警報仍成立，標示不能完整定位；部分剝離不當完整差集 |

新增完成分支檢查回傳 0 的同一次呼叫是否有拒絕且沒有接受。符合時另外警報並提供被拒項目，不改動 IBLT 差集。新增配對失效不取消有效的原身分差異警報，原身分一致而新配對失效時，整體無法判定。詳見[完整判讀表](CALL_COMPLETION_20261103_zh-TW.md)。

名稱、inode 與型態共同構成本文比對的身分。差異動作中的改名與欄位修改是改寫回傳記錄，不等於修改磁碟上的檔案。型態與 inode 供程式後續處理使用，因此納入比較有功能上的理由，實際工具受何種影響則未另實測，見[文獻與界線](REVIEW_CORRECTIONS_20261102_zh-TW.md)。

各組實驗的單位與條件不同，樣本數分開計算。先導、故障注入與未修改原版對照不混入確認分母。第二輪另有 252 次新增因空間不足未實際注入，包含 240 次量測及 12 次控制；它們不算成功陽性。

原診斷版與合併版的全域 map memlock 約為 7.50 MiB 與 2.60 MiB，256-cell 邏輯摘要仍約 12.02 KiB。前者不是摘要 bytes、整工具實體峰值或流量。候選每筆預留 256 cells、上限 256 執行緒，只實測 16 程序併發，不能宣稱上限已全面驗證。

## 完整性檢查仍有限制

返回 profile 的 missed 是事件全域窗口讀數，合計受測核心的內部 kprobe 與返回實例漏失。現行入口另明確建立 tracefs 入口事件並查其 nmissed，保留 BPF recursion_misses。缺統計、身分錯誤、倒退或新增漏失均拒判。這已解決原清單要求的可觀測來源接入，不代表所有量測故障都可觀察，也不能替原資料補零。

診斷版的 original_valid 含新增收支檢查，不等同未修改原版。另以原判定函式作的 56 次漏失／56 次對照已分開保存，本輪沒有展示舊版錯誤一致被修復。詳見[更正](../phase1/CORRECTIONS_zh-TW.md)。

## 可信假設與觀測範圍

仍假設 eBPF、C 掃描器及控制程式未被攻擊者控制，受測模組不依種子或偵測器調整行為。沒有建立種子保密機制、主動碰撞安全證明或外部信任域。

filldir64 之前排除的項目、提早回傳 0 後尚未走訪的項目、只在 libc 等程式庫返回後過濾，以及只向掃描器回傳完整資料，都不是這次已驗證可處理的情形。函式庫觀測點列為下述研究提案，第一端之前的視圖不加入本次。政策過濾仍會警報，惡意性與授權判定沒有加入本方法。

## 下一步

下一步聚焦增加觀測點，研究差異出現在哪一段。保留同次列舉與固定摘要的原則，規劃對齊核心已接受項目、getdents64 回傳記錄及程式經函式庫取得的項目，再比較相鄰兩端。

這是尚未實作的研究提案。須先處理函式庫批次讀取與逐筆交付的配對、未完成列舉及缺失資料，再以正常、受控核心過濾、受控函式庫過濾驗證差異區段、無效率與成本。區段差異仍不直接代表惡意。具體說明與文獻見[報告修正依據](REVIEW_CORRECTIONS_20261102_zh-TW.md)。

原版 CARAXES 受測的同次拒絕後回報結束，現已另以完成檢查實作驗證，不再列為尚未實作。未走訪的後續項目仍未知，完整清單須另有可信參照與時間條件，增加函式庫端觀測本身不能補回。

IBLT 容量與重複差異、可信量測及未受測環境保留在方法限制中。還原核對、入口漏失拒判及 zygarde 比較已完成。金鑰保護、辨識掃描器、單純換成 /proc、預編譯或掃描整個檔案系統，不另列為本研究的下一步。
