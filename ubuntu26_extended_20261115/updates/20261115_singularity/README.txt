Singularity 已完成的目錄隱藏矩陣
更新時間：2026-11-15T23:22:15.616636+08:00

結論：釘選的原版模組可在 Ubuntu 26、7.0.0-43-generic 載入並產生目錄隱藏。偵測器在本次目錄條件下可告警並解出實際觀測差異。

範圍：ext4、tmpfs；自動化測試腳本使用 256 與 65,536 bytes 的 getdents64 緩衝區；每個檔案系統 20 組 fixture。兩種探針啟用順序各使用三個乾淨開機，共六個獨立開機、1,920 次正式掃描。另 324 次先導觀測不併入正式分母。
兩種順序指 eBPF 探針在模組插入前／後啟用；Python 程式與相依套件均在插入前匯入。這不是完整受感染環境下的軟體安裝測試。

正式結果
• 隱藏測試：480/480 次告警。
• 正常對照：0/1440 次差異告警。
• 量測無效：0 次。480/480 次有效陽性完整解碼當次觀測到的 K↔S 差異。


證據與版本
• upstream commit：074f3852240bf9c37bc9173cb34efa8e9f668798
• 模組 SHA-256：bd544564fd1412665b531c6b32032af0421977817681ce4f6078b03583e00e49
• 原始碼未修改，未執行安裝／持久化腳本；每組結束後以重開機清除樣本，再取得原始資料。
• 先導試驗發現載入期間匯出的 tar 僅能讀到一個項目；重開機後重新匯出有 662 個項目。正式矩陣因此全部在重開機後取回資料。沒有將首次不完整匯出當成準確率證據，也未將原因追認成某個已定位的 hook。
• 六組原始 syscall bytes、完整名稱／inode／型態真值、K 端 IBLT、量測紀錄和原始壓縮包保存在本機 artifacts/ubuntu26_extended_20261115_run10，GitHub 提供彙總、逐次表、協定與來源雜湊。

可放入報告的敘述
「在 Ubuntu 26 的指定核心與釘選 Singularity 版本下，跨兩種探針啟用順序、各三次開機的目錄測試中，480 次隱藏觀測皆產生差異告警，1,440 次正常對照未產生差異告警。已觀測到的核心／syscall 差異均可完整解碼。」

完成範圍僅為上述目錄矩陣；Singularity 的 /proc、同 VM inode/debugfs 取檔及組合樣本矩陣未包含在這次結果中，整個原計畫仍未全部完成。
